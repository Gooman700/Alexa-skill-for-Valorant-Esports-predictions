\section{Amazon Alexa and Google Assistant}
In the domain of voice-activated smart speakers, the market is primarily led by two ecosystems: Amazon Echo and Google Home. Both systems utilise virtual assistants---Alexa and Google Assistant, respectively---which are activated via a specific wake command, such as ``Alexa'' or ``Hey Google''. These platforms allow third-party developers to create bespoke applications, referred to as `skills' in the Amazon ecosystem and `actions' within Google's, which can be invoked by users to extend the device's functionality.

Data provided by Statista Consumer Insights indicates that Amazon maintains a significantly larger market share compared to Google in the smart speaker sector (\autoref{fig:SmartSpeakerChart}). Consequently, the Amazon Alexa platform represents a more strategic target for development, offering a broader potential user base for the deployment of new predictive tools.

A critical limitation was identified during the evaluation of the Google Home ecosystem. Google has recently deprecated `conversational actions' in favour of `app actions', as documented in the Assistant Developer documentation\cite{google_sunset}. This shift implies that new Google Assistant developments must be tethered to a corresponding Android application. Given that this project is intended to function as a standalone voice service without a prerequisite mobile app, the sunsetting of conversational actions effectively precludes Google Home as a viable system. Therefore, the decision was made to proceed exclusively with the Amazon Alexa platform.

\section{Programming Language Selection}
Selecting an appropriate primary programming language is a critical decision, as the choice directly influences the availability of documentation, pre-built libraries, and the overall complexity of the implementation. A language with insufficient support for machine learning would necessitate the manual development of boilerplate code, increasing the risk of project delays. Conversely, a language with an excessively steep learning curve could impede the preliminary stages of development. Therefore, a balance between technical capability and development efficiency must be established.

Following a comparative evaluation of the supported environments for Alexa Skill development, Python was quickly identified as the optimal language for this project. Python is widely regarded as the industry standard for machine learning and data science, offering an extensive ecosystem of libraries that abstract complex mathematical operations and reduce manual implementation. The language's syntax and conventions further contribute to code readability and long-term maintainability. The following libraries were identified as essential to the project's success:

\begin{itemize}
\item \textbf{NumPy:} This library facilitates high-performance operations on multidimensional array objects. NumPy is reported to be significantly more efficient than standard Python lists, which is crucial when processing the large datasets typical of machine learning workflows. \cite{numpy_site}
\item \textbf{pandas:} This provides a high-performance DataFrame object for structured data manipulation. It includes integrated tools for reading and writing data in various formats, such as CSV, and offers a powerful engine for aggregating and merging disparate datasets. \cite{pandas_site}
\item \textbf{scikit-learn:} A comprehensive suite of machine learning tools, including various classification algorithms, utilities for data splitting (training and testing sets), and metrics for evaluating model performance. \cite{sklearn_site}
\end{itemize}

\section{The Dataset}
\label{sec:dataset}
To develop a machine learning model with predictive power beyond stochastic guesswork, a meaningful set of features must be identified and obtained. Within the context of a Valorant match, data granularity ranges from high-level outcomes, such as the overall winner, to round-specific metrics, such as individual elimination counts. This spectrum of data allows for an iterative development approach: a model may be initialised using a small subset of primary features, with more complex, derived features integrated during later stages of implementation.

Two primary methods for acquiring a suitable dataset were evaluated: manual creation via web-scraping or the utilisation of a pre-existing dataset. The manual creation of a dataset would require the development of a bespoke web-scraper to request the HTML content of match results from historical VCT data since 2021. Extracting features from a repository such as VLR.gg \cite{vlr_gg} would involve querying the DOM using feature unique CSS selectors, such as \texttt{\#wf-title-med} for the team names. While this method offers maximum control over the data schema, the process of extraction, standardisation, and anomaly detection is substantially time-consuming.

Conversely, the use of an existing dataset requires an investigatory assessment of feature richness and data integrity. It is essential to ensure that the dataset captures the underlying relationships between match variables and the final outcome without introducing multicollinearity---a state where redundant features communicate identical information. Furthermore, any external data must be used in strict accordance with the original author's licensing and copyright terms.

Given the significant time investment required for manual scraping, the acquisition of a comprehensive, pre-existing dataset was prioritised. A suitable dataset was identified and sourced from a repository on Kaggle \cite{ryanluong_dataset}. \autoref{tab:key-dataset-features} provides a data dictionary of the critical features extracted for this project. An exhaustive list of features provided with the dataset are listed in \autoref{tab:data-dictionary}. The data is structured into annual folders such as `vct_2025' representing independent yearly data. Each folder contains the IDs of each entity present within the data, such as players, teams, and matches, within a folder called `ids'. Additionally, there exists data pertaining to player statistics, match statistics, and agent statistics. Notably, a master folder `all_ids' contains files to record the ID mappings for every entity across all years, which will be useful in providing unique keys to merge tables on. A visual representation of the structure can be seen in \autoref{fig:dataset-folder-structure} below. Please note that the structure for years 2021 to 2024 are identical to 2025.

\section{Exploring Machine Learning Approaches}
Machine learning (ML) is defined as a ``field of artificial intelligence concerned with the development of statistical algorithms capable of learning from data to generalise to unseen instances, thereby performing tasks without explicit instructions'' \cite{Koza1996}.

The ubiquity of ML is evident in modern digital infrastructure. For instance, platforms such as Facebook utilise ML to generate estimated action rates and ad quality scores within a total value equation to optimise user engagement \cite{Facebook2020}. With a monthly active user base exceeding three billion as of late 2025 \cite{NaveenKumar2025}, such systems represent a significant industrial application of predictive modelling. More pertinently to this research, the sports betting industry has shifted towards predictive ML models to generate odds and quantify the probability of specific match outcomes \cite{RhysGregory2025}. This industrial application directly mirrors the objectives of this project, albeit applied to the esports domain.

To achieve the stated aims, a suitable machine learning paradigm must be selected. Algorithms are generally categorised into four primary frameworks: supervised, unsupervised, semi-supervised, and reinforcement learning \cite{Sarker2021}. The selection of an appropriate framework is dependent not only on the desired task but also on the nature of the available data.

In the context of Valorant match prediction, the choice of paradigm is dictated by the structure of the VCT dataset. As professional matches result in a definitive winner and loser, the historical data is inherently labelled. Consequently, supervised learning is identified as the most appropriate approach for this project. Unlike unsupervised learning, which is designed for exploratory pattern discovery in unlabelled data, supervised learning is optimised for classification tasks where the goal is to predict a specific target variable (the match winner) based on known historical inputs.
 
\subsection*{Supervised Learning}
Supervised learning is the process of teaching a machine by example. The algorithm is provided with a dataset where the human knows the correct outputs for the set of inputs. The machine makes predictions using the provided data, and is corrected when wrong, until the algorithm has been refined enough for there to be a high degree of \gls{accuracy}. This approach is well suited to predicting or classifying new, unseen data based off of the patterns recognised from the labelled training data. However, supervised learning is not as good at discovering new patterns, only at predicting based off of existing ones. Also, it requires a sufficiently large, accurately labelled dataset, which is time-consuming and expensive to procure/produce. \cite{SupervisedLearning}

\subsection*{Unsupervised Learning}
Unsupervised learning is where the machine studies large, unlabelled datasets to pick out patterns and organise the data in some way. There is no correction taking place from the human, since the data is not labelled. Given a large set of data, and without human input, unsupervised learning algorithms will discover hidden patterns or data groupings automatically. Unsupervised learning lends itself nicely to exploratory data analysis, being able to collate data points into separate 'clusters', or to identify outliers and anomalies from a dataset. Usually, the datasets used are acquired 'cheaply', such as web-crawling, where there is an enormous quantity of data available without a large cost. Unsupervised learning is however less useful when a precise output is required. Due to the nature of being trained on unlabelled data, the machine doesn't know what right answers are, only outputting the patterns it sees, in many cases being categories that are not meaningful or relevant \cite{TeamDigitalDefynd:online}.

\subsection*{Semi-supervised Learning}
Semi-supervised learning is an approach that combines supervised and unsupervised learning by using both labelled and unlabelled datasets. Semi-supervised learning is commonly utilised for the same contexts as supervised learning models; however semi-supervised models also harness unlabelled data when training, alongside the existing labelled data. It is useful for machine learning tasks where a sufficient quantity of labelled data is prohibitively difficult or expensive to obtain, but a large quantity of unlabelled data isn't. Both supervised and unsupervised learning would underperform in such a situation. Semi-supervised learning is less efficient than its already mentioned counterparts when enough labelled data can be gathered to use supervised learning—in which case results will be better due to the correction taking place—or when there is a severe lack or inability to gather labelled data, in which case unsupervised learning would be used. \cite{DaveBergmann}

\subsection*{Reinforcement Learning}
Finally, reinforcement learning (RL) is where an `agent' will, through trial and error, learn to maximise its `reward' by making certain decisions. In contrast to supervised and unsupervised learning, RL requires a dataset that consists of state-action-reward sequences. The data points are arranged into an environment for the machine to interact with—where states have transitions to other states—and there is a set goal for the machine to aim for. Initially, the machine will choose random actions from the predefined set available, and it will receive feedback on how each action contributed towards making it closer to the goal. Over time, the machine will assign weights to the actions, proportional to the size of the reward that it received for completing that action. This will lead to the machine choosing, at each time step, the actions that it has been told are the best ones. RL is a good choice for tasks that involve sequential decision making to maximise a long-term cumulative reward. For example, teaching a machine to play games, or to learn dexterity. RL is less suited when tasks don't have clearly defined rewards, and shouldn't be used for tasks with potential danger involved \cite{Hoda2020}.  RL has been used for many different tasks, such as teaching a machine to play Go\footnote{An overview of Go: \url{https://en.wikipedia.org/wiki/Go_(game)}} from scratch, by playing against itself for 40 days. This model was called AlphaGo Zero, and it was able to outperform the previous Go AI that famously beat the world number one Ke Jie, and Lee Sedol \cite{silver2017mastering, lee2016human}.

\noindent A comparative analysis of these machine learning paradigms reinforces the conclusion that supervised learning is the optimal approach for this project. This selection is dictated by the structure of the VCT dataset established in \autoref{sec:dataset}, which consists of historical professional matches with definitive, labelled outcomes (a confirmed winner and loser).

Furthermore, the primary objective is to generate \textit{accurate predictions} of match results rather than to perform exploratory \textit{pattern discovery}, for which unsupervised learning would be better suited. The tabular nature of the match statistics does not readily lend itself to a state-action-reward environment required for reinforcement learning, and the abundance of labelled data precludes the necessity for semi-supervised techniques. \section{Machine Learning Algorithms}

\subsection{Related Work in Predictive Sports Analytics}
The application of supervised learning to match outcome prediction is well-documented within traditional sports literature. A significant portion of existing research has focused on football; for instance, Igiri and Nwachukwu \cite{igiri2014improved} developed improved prediction systems by leveraging historical match results, while Owramipur et al. \cite{owramipur2013football} utilised Bayesian networks to predict outcomes in the Spanish League, highlighting the effectiveness of probabilistic modelling in competitive environments.

Comparative studies have frequently been employed to identify the most effective algorithms for sporting data. Delen et al. \cite{delen2012comparative} conducted a comprehensive analysis of ML methods to predict NCAA bowl outcomes, concluding that ensemble-based approaches often outperform individual classifiers. In addition, Mustafa et al. \cite{mustafa2017predicting} compared various machine learning methods in the context of cricket, noting that the inclusion of diverse feature sets---including social sentiment and historical form---significantly enhances predictive accuracy.

Furthermore, the concept of ``one-match-ahead" forecasting, as explored by Lam \cite{lam2018one}, demonstrates the utility of Bayesian regressions in handling the sequential nature of two-team sports. While these studies primarily address traditional athletics, the underlying mathematical principles are directly transferable to the esports domain. Like football or cricket, Valorant matches are defined by two-team interactions, historical form, and situational variables (such as map choice), justifying the application of these established classification frameworks to the VCT dataset.

\subsection*{Logistic Regression}
Logistic regression is a linear classifier model developed for binary classification problems, though multi-class implementations also exist. The model transforms the output of a linear equation into a probability bound between zero and one using the Sigmoid (Logistic) function:
\begin{equation*}
    P = \frac{1}{1+e^{-x}}
\end{equation*}
Where $P$ represents the probability of a specific outcome occurring. Logistic regression is valued for its simplicity, ease of implementation, and high degree of interpretability, making it an ideal choice for establishing a performance baseline. However, the model assumes a linear relationship between the independent variables and the log-odds of the dependent variable. This assumption often renders it less effective for modelling complex, non-linear relationships found in high-dimensional real-world data \cite{osisanwo2017supervised}.

Despite these theoretical limitations, logistic regression has demonstrated remarkably high accuracy in sporting contexts where feature sets are meticulously curated. For instance, Igiri and Nwachukwu \cite{igiri2014improved} achieved a predictive accuracy of 93\% in football match forecasting by applying logistic regression to a dataset of 9 key features. Conversely, in studies where more rigorous validation techniques were employed, the results were more conservative; Zaveri et al. \cite{zaveri2018prediction} utilised 10-fold cross-validation on a 12 feature dataset, resulting in a more modest accuracy of 71.63\%. These varied results suggest that while logistic regression is a powerful baseline tool, its performance is highly sensitive to both the quality of feature engineering and the specific validation methodology used.

\subsection*{K-Nearest Neighbours}
K-Nearest Neighbours (KNN) is a non-parametric model utilised for both classification and \gls{regression} tasks. The algorithm operates by calculating the distance between a new query point and all existing points in the training dataset, identifying the $K$ nearest instances to formulate a prediction. In a classification context, the output is determined by a majority vote among these $K$ neighbours, whereas in regression, the mean value of the neighbours is typically calculated. The hyperparameter $K$ is manually specified and must be optimised to balance predictive accuracy against computational latency.

Unlike ``eager'' learners that construct an internal model during a training phase, KNN is a ``lazy'' learner that retains the entire dataset in memory. Consequently, the algorithm is computationally expensive and memory-intensive, as a full scan of the dataset is required for every prediction. Furthermore, KNN is highly susceptible to the ``curse of dimensionality.'' As the number of features increases, the volumetric space expands so rapidly that the available data points become sparse. This causes the distance between the nearest and furthest neighbours to converge, significantly degrading the model's ability to discern patterns \cite{osisanwo2017supervised}.

Horvat et al. \cite{horvat2018prediction} applied KNN to a basketball dataset containing 15 distinct features, achieving an accuracy of 83.96\%. Whilst this result is high, the extreme computational cost associated with processing the extensive feature sets typical of modern esports metrics could cause the Alexa skill to time-out on the user. Alexa skills have a default eight-second window to deliver a response, after which the intent is terminated. Since KNN models require distance calculations to be performed on all data points for each query, a complex model could exceed the time-out limit, resulting in a more negative user experience.

\subsection*{Support Vector Machines (SVM)}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\linewidth]{./images/Support Vectors.png}
    \caption{Visualisation of SVM Hyperplane and Support Vectors}
    \label{fig:SVM}

Support Vector Machines (SVM) function by identifying the optimal hyperplane that separates data points of different classes within a high-dimensional feature space. This hyperplane is determined by maximising the margin between the closest points of each class, which are formally known as support vectors. The goal is to create a decision boundary that is as far as possible from the nearest training instances of any class, thereby enhancing the model's generalisability.

SVMs are particularly versatile due to the use of kernel functions—such as Linear, Polynomial, or Radial Basis Function (RBF)—which project the input data into higher-dimensional spaces where classes that were originally non-linear can become linearly separable. While highly effective for high-dimensional datasets, SVMs can be computationally expensive and require meticulous tuning of hyperparameters, specifically the regularisation parameter $C$ and the kernel coefficient $\gamma$ \cite{osisanwo2017supervised}.

The efficacy of SVMs in sports analytics is demonstrated by Mustafa et al. \cite{mustafa2017predicting}, who utilised the algorithm to predict cricket match outcomes. By employing 10-fold cross-validation, the study achieved a predictive accuracy of 87.90\%, outperforming several other classifiers. The research highlighted that SVMs are particularly effective when dealing with the diverse, multidimensional feature sets—such as social sentiment and player form—that are characteristic of competitive sports. Similarly, Kravanja \cite{kravanja2013napovedovanje} applied SVMs to a smaller basketball dataset using 3-fold cross-validation, achieving an accuracy of 70.01\%.

\subsection*{Random Forest}
Random Forest is an ensemble learning method constructed from a multitude of decision trees, applicable to both classification and regression tasks. The algorithm operates by building numerous decision trees during the training phase; for classification, the final output is determined by a majority vote across all trees, whereas for regression, the average of the individual tree predictions is calculated.

The primary advantage of the Random Forest architecture is its inherent resistance to overfitting, a common failure for individual decision trees. This is achieved through two layers of randomness. Each tree is trained on a bootstrap sample of the data (bagging), and a random subset of features is considered at each node split. This stochastic process ensures diversity amongst the constituent trees, leading to a more generalised model. Furthermore, Random Forests provide inherent feature importance metrics, allowing for an empirical assessment of which match variables most significantly impact the final prediction \cite{osisanwo2017supervised}.

In practical sports forecasting, Random Forests have demonstrated consistent reliability across diverse datasets. Knoll and St{\"u}binger \cite{knoll2020machine} attained a predictive accuracy of 75.62\% when applying the algorithm to football match outcomes, noting its ability to handle non-linear interactions without the extensive kernel tuning required by SVMs. Similarly, Lin et al. \cite{lin2014predicting} achieved an accuracy of 65.15\% on a dataset featuring 16 distinct variables pertaining to basketball.

These results are particularly relevant to the Valorant Champions Tour (VCT) context, as the varied team compositions and map-specific anomalies in esports often introduce noise that would cause simpler models to overfit. However, the memory-intensive nature of storing a large forest of trees must be considered. As the number of trees increases to improve accuracy, the model's footprint expands, which may impact the loading times and execution efficiency of the Python backend within an AWS Lambda environment.

\subsection*{Gradient Boosted Trees}
Gradient Boosted Trees (GBT) represent an ensemble learning technique that constructs a predictive model through the sequential addition of decision trees. Unlike Random Forest, which builds trees in parallel (bagging), GBT employs a boosting strategy where each successive tree is specifically trained to reduce the residual errors of the preceding one. This optimisation is achieved through gradient descent, allowing the model to minimise a loss function and capture intricate, non-linear patterns within the data.

GBT architectures, such as XGBoost and LightGBM, are renowned for their high predictive accuracy and frequently outperform simpler linear or bag-based models on structured datasets. However, this increased performance comes at the cost of careful hyperparameter tuning; parameters such as the learning rate ($\eta$), tree depth, and the number of boosting iterations must be carefully balanced, as without proper regularisation, GBT models are highly susceptible to overfitting, particularly on datasets with a high degree of noise \cite{osisanwo2017supervised}.

For this project, gradient boosted trees---and specifically the LightGBM implementation---is identified as a good candidate for the final model. Given the eight-second latency limit of the Amazon Alexa platform, the leaf-wise growth strategy of LightGBM typically offers faster training and inference speeds than traditional depth-wise GBT implementations. This ensures that the model can maintain high accuracy while remaining within the technical constraints of the hosting platform.
